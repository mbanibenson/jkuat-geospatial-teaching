HTML: the structure

HTML says what each part of the page is: a heading, a list, a sidebar, a box for the map. It says nothing about how they look. That is Step 2.

Anatomy of an element

<p class="subtitle">EGE 2531 · Week 2 practical</p>

PartHereMeaning
Opening tag<p class="subtitle">"A paragraph starts here"
Attributeclass="subtitle"Extra information about the element, written name="value" inside the opening tag
ContentEGE 2531 · Week 2 practicalWhat the element contains: text, or other elements
Closing tag</p>"The paragraph ends here". Same name, with a slash
Elementthe whole lineOpening tag + content + closing tag

A few elements have no content and no closing tag, for example <meta>, <link> and <input>. They are called void elements.

Elements nest. An element can contain other elements, like folders inside folders. <ul> contains <li> items, and <aside> contains the heading, the paragraph and the list. The result is a tree, and in Step 4 JavaScript walks that tree to find elements and change them. Indent your code so you can see the tree. The browser ignores indentation; you should not.

id: a unique name. Only one element on the page may have id="map". Leaflet finds its map container by id next week.

class: a group. Many elements can share class="sidebar", and one element can have several classes.

CSS: selectors and layout

CSS says how elements look and where they sit. The goal is the layout of almost every web map: a header on top, a fixed-width sidebar on the left, and a map that fills the rest of the window.

Anatomy of a rule

CSS 
.site-header h1 {
  margin: 0;
  font-size: 1.4rem;
}

The selector (.site-header h1) says which elements the rule applies to. Each declaration inside the braces is a property: value; pair. The semicolons matter. A missing one silently breaks the next line.

SelectorWrittenMatchesIn our page
Elementh1Every <h1>Top-level headings
Class.sidebarEvery element with class="sidebar"The <aside>
Id#mapThe one element with id="map"The map box
Descendant.site-header h1<h1> inside .site-headerThe title only
Grouphtml, bodyBothThe page root

The dot means class and the hash means id, here and again in JavaScript in Step 4. When two rules disagree, the more specific selector wins: an id beats a class, and a class beats an element. If they are equally specific, the later rule wins.

The box model

Every element is a rectangle made of four layers, from the inside out: content, padding (space inside the border), border, and margin (space outside it, pushing neighbours away). By default width: 320px sets only the content width, and padding and border are added on top. * { box-sizing: border-box; } makes 320px mean the whole box. Every sensible stylesheet starts with it.

Flexbox

display: flex lays a container's children out in a row, or in a column with flex-direction: column. A child with flex: 1 takes all the space left over. We use it twice. body is a column, and main gets flex: 1, so it takes all the height below the header. main is a row, and #map gets flex: 1, so it takes all the width beside the 320px sidebar.

In this step JavaScript writes the facility list itself, and two filters redraw it. This is how every interactive map works: the data lives in JavaScript, and the page is redrawn from it.

// Step 4 — the DOM and events.
// The facility list is now written by JavaScript, and the filters redraw it.

const facilities = [
  { name: "Juja Level 5 Hospital", level: 5, beds: 301, operational: true, lon: 36.673763, lat: -0.804421 },
  { name: "Ruiru Health Centre", level: 3, beds: 32, operational: true, lon: 36.71698, lat: -0.893475 },
  { name: "Kikuyu Health Centre", level: 3, beds: 45, operational: false, lon: 36.846252, lat: -0.985171 },
  { name: "Juja Dispensary", level: 2, beds: 2, operational: true, lon: 36.671381, lat: -1.186882 },
  { name: "Githunguri Sub-County Hospital", level: 4, beds: 135, operational: true, lon: 36.942477, lat: -1.084828 },
];

// Find the elements once. querySelector takes a CSS selector — the same ones as style.css.
const levelSelect = document.querySelector("#level-select");
const operationalBox = document.querySelector("#operational-only");
const statusEl = document.querySelector("#status");
const listEl = document.querySelector("#facility-list");

// Does this facility pass the current filters?
function matchesFilters(facility) {
  const minLevel = Number(levelSelect.value);   // .value is always a string
  if (facility.level < minLevel) return false;
  if (operationalBox.checked && !facility.operational) return false;
  return true;
}

// Redraw the list from the data. Called at the start and after every change.
function render() {
  const shown = facilities.filter(matchesFilters);
  statusEl.textContent = `Showing ${shown.length} of ${facilities.length} facilities`;

  listEl.innerHTML = "";                         // empty the list
  for (const f of shown) {
    const li = document.createElement("li");     // make a new <li>
    li.textContent = `${f.name} — level ${f.level}, ${f.beds} beds`;
    if (!f.operational) li.classList.add("closed");
    listEl.appendChild(li);                      // put it in the <ul>
  }
}

// Events: "when this control changes, run render".
levelSelect.addEventListener("change", render);
operationalBox.addEventListener("change", render);

render();

Follow the flow. On load, render() runs once and draws 5 facilities. When the user picks "Level 4 and above", the browser fires change and calls render again. render reads the filters, filters the array, empties the list and rebuilds it. The data never changes. Only the view of it does.

fetch, promises and async/await

Five hand-typed facilities is not a map. In this step the page loads all 60 from data/facilities.geojson over HTTP, the same way it will later load from PostGIS and GeoServer. There is one idea to understand, and it causes more confusion than anything else in this unit: JavaScript never waits.

Why it does not wait

Python runs a line, waits for it to finish, and moves on. A browser cannot: while it waited two seconds for a file over a slow network, nothing on the page could be clicked or scrolled. So fetch returns immediately with a promise, an object that stands for "the result, once it arrives". Your code tells the promise what to do when it arrives, and carries on.

Paste this into the Console (the one time pasting is fine):

Console 
const wait = ms => new Promise(resolve => setTimeout(resolve, ms));
console.log("A");
wait(2000).then(() => console.log("C"));
console.log("B");

It prints A, B, and C two seconds later. .then(…) means "when this promise is fulfilled, run this function".

The bug everyone writes

You will write this at least once this semester:

// WRONG — data is still undefined when the last line runs
let data;
fetch("data/facilities.geojson").then(r => r.json()).then(d => { data = d; });
console.log(data.features.length);   // TypeError: Cannot read properties of undefined

Nothing is broken. The fetch has not finished when the last line runs. The fix is always the same: do the work inside the handler, the code that runs once the data has arrived.

Two ways to write it correctly

JavaScript 
// 1. With .then() — a chain of "and when that's done..."
fetch("data/facilities.geojson")
  .then(response => response.json())
  .then(geojson => console.log(geojson.features.length))
  .catch(err => console.error("failed:", err));

// 2. With async/await — reads top to bottom, like Python
async function load() {
  const response = await fetch("data/facilities.geojson");
  const geojson = await response.json();
  console.log(geojson.features.length);
}
load();

await means "pause this function until the promise settles". The rest of the page keeps running. await works only inside a function marked async. We use async/await from here on because it reads like Python. Examples online use both styles, so learn to recognise both.

A Feature, as JavaScript sees it

GeoJSON 
{
  "type": "Feature",
  "properties": { "name": "Ngewa Health Centre", "county": "Kiambu", "level": 3, "beds": 47, "operational": true },
  "geometry": { "type": "Point", "coordinates": [36.62885, -1.177803] }
}

The attributes are in feature.properties. The location is feature.geometry.coordinates, written [longitude, latitude]: x first, then y. The new code turns each Feature into the flat object render() already understands, so nothing else changes.

// Turn one GeoJSON Feature into the flat object the rest of the code expects.
// GeoJSON coordinates are [longitude, latitude] — x first, then y.
function toFacility(feature) {
  const p = feature.properties;
  return {
    name: p.name,
    level: p.level,
    beds: p.beds,
    operational: p.operational,
    lon: feature.geometry.coordinates[0],
    lat: feature.geometry.coordinates[1],
  };
}

// async lets us write await: "pause THIS function until the promise settles".
// The rest of the page keeps running while we wait.
async function loadFacilities() {
  try {
    const response = await fetch(DATA_URL);
    if (!response.ok) {
      // fetch does NOT fail on a 404 — we have to check ourselves
      throw new Error(`HTTP ${response.status}`);
    }
    const geojson = await response.json();
    facilities = geojson.features.map(toFacility);
    render();          // only now is there anything to draw
  } catch (err) {
    statusEl.textContent = `Could not load the facilities (${err.message}). Is Live Server running, and is the file in data/?`;
    statusEl.classList.add("error");
    console.error(err);
  }
}

levelSelect.addEventListener("change", render);
operationalBox.addEventListener("change", render);

loadFacilities();
  • geojson.features.map(toFacility) builds a new array by calling toFacility on every Feature. It is Python's [to_facility(f) for f in features].
  • render() is called inside loadFacilities, after the data has arrived. That is the fix for the bug above.
  • try { … } catch (err) { … } is Python's try/except. The user sees a message they can act on instead of an empty page.
  • fetch does not treat 404 as an error. A "not found" reply is still a reply. Check response.ok yourself.

A map with no mapping library

In this step you plot each facility as a dot inside #map by converting longitude and latitude into screen positions. It is a crude map, deliberately so. What goes wrong with it is the best explanation of what Leaflet does for you next week.

Choose a box of the world to draw. Roughly, Kiambu is 36.5°E to 37.4°E and 1.35°S to 0.75°S. A facility's position across the box is how far its longitude is from the west edge, as a fraction of the width. Its position down the box is measured from the north edge, because screens count downwards and latitude counts upwards:

x = lon − westeast − west     y = north − latnorth − south

Both run from 0 to 1 inside the box. Multiplied by 100, they become CSS percentages for left and top.

6.1In app.js, under the other querySelector lines

JavaScript 
const mapEl = document.querySelector("#map");

// The box of the world we are drawing: roughly Kiambu County, in degrees.
const BOUNDS = { west: 36.5, east: 37.4, south: -1.35, north: -0.75 };

6.2Add drawDots, and call drawDots(shown); as the last line of render()

JavaScript 
// Place one dot per facility. left/top are percentages of the #map box.
function drawDots(list) {
  mapEl.innerHTML = "";
  for (const f of list) {
    const x = (f.lon - BOUNDS.west) / (BOUNDS.east - BOUNDS.west);    // 0 at west edge, 1 at east
    const y = (BOUNDS.north - f.lat) / (BOUNDS.north - BOUNDS.south); // 0 at top, 1 at bottom: screens count downwards

    const dot = document.createElement("div");
    dot.className = `dot level-${f.level}`;
    dot.style.left = `${x * 100}%`;
    dot.style.top = `${y * 100}%`;
    dot.title = `${f.name} (level ${f.level})`;   // hover to see the name
    if (!f.operational) dot.classList.add("closed");
    mapEl.appendChild(dot);
  }
}
